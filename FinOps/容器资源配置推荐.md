# 容器资源配置推荐
## 资源配置推荐标准

> server：服务容器
> 
> istio-proxy：istio Sidecar容器

### 容器CPU利用率查询语句

```text 💡 
(sum by(cluster,container) (rate(container_cpu_usage_seconds_total{cluster="$cluster", pod=~"^$service-[a-z0-9]+-[a-z0-9]+$", namespace=~"$namespace"}[$__rate_interval])) * 100) / sum by(cluster,container) (kube_pod_container_resource_requests{resource="cpu", cluster="$cluster", pod=~"^$service-[a-z0-9]+-[a-z0-9]+$",namespace=~"$namespace"})
```

### 资源倍数推导公式

> 通过一些有代表性的业务指标或服务预估最小容量与最大容量的倍数关系
> 
> 数据统计周期：1周

- 在线人数

    - Max: 3000
    
    - 比例3倍

- api-gateway QPS

    - max：120K

- xx A服务 CPU

        - min：2
        
        - max：12
        
        - 比例：6
    
    - service：
        - min：2
        
        - max：10
        
        - 比例：5

- Xx B服务 CPU
    - istio-proxy：

从上面分析，业务高低峰差值在3-8倍，正常服务最少3个pod（k8s节点容灾分布在三个可用区），最多为3*8=24

### cpu水位推荐

> 如下为常规服务场景下的推荐，特殊服务需要有针对性的配置

最大值：取一周最高CPU使用量

最小值：取一周最低CPU使用量

#### 档位标准

> 1. 不推荐 request 过大，如果大于5，可以通过降低 request，增加 pod 数据来解决
> 
> 2. 不推荐 pod 数过多，一般不超过30个

| 档位 | request  | HPA阈值 | limit设置标准 |
| --- | --- | --- | --- |
| 一档 | 0.1 - 0.6 | CPU 小于等于 150% | request*4 |
| 二档 | 0.6 - 1.5 | CPU 小于等于 120% | request*3 |
| 三档 | 1.5 - 3 | CPU 小于等于 100% | request*2 |
| 四档 | 3 - 5 | CPU 小于等于 80% | request*1.8 |
| 五档 | 5 以上 | CPU 小于等于 70% | request*1.5 |

#### CPU Request 推荐值

> k8s 计算 HPA 是计算所有容器的资源。（高版本的k8s集群可以根据指定的容器进行 hpa 配置）
> 
> 需要 server 容器与Sidecar容器 CPU 利用率尽量保持在一条线
> 
> 如果发现 HPA 不生效或者频繁的缩扩容，说明 server 容器与 Sidecar 容器的CPU利用率为重合，需要具体问题具体分析再做调整

```python
# 场景一：可以弹性伸缩的服务。
week_min_use_server_cpu = 最近一周使用最小 CPU 核数
week_min_use_istio_cpu = 最近一周使用最小 CPU 核数
min_pod_num = 3
# 按照最小的容器数量为3计算
server_cpu = week_min_use_server_cpu / 3
istio_cpu = week_min_use_istio_cpu / 3
# 如果 istio 集群规模较大，且对 xds 下发范围未做控制，istio_cpu 最小配置为 0.5
if istio_cpu < 0.5:
    istio_cpu = 0.5

# 如果大于 5C，需要扩大 min_pod_num 数量
if server_cpu > 5:
    server_cpu = 5
if istio_cpu >5:
    istio_cpu = 5
min_pod_num = max(week_min_use_server_cpu / 5, week_min_use_istio_cpu / 5)
    
request = server_cpu + istio_cpu
# 根据计算的 request 值，根据档位得到 limit 和 HPA 阈值

 # 场景二：尽量不伸缩的服务。
week_max_use_server_cpu = 最近一周最大使用cpu
week_max_use_istio_cpu = 最近一周最大使用cpu
pod_num = 需要计算的数量
# 计算 min_pod_num
pod_num = max(week_max_use_server_cpu / 5, week_max_use_istio_cpu / 5, 3)

 # 场景三：不允许伸缩
 week_max_use_server_cpu = 最近一周最大使用cpu
week_max_use_istio_cpu = 最近一周最大使用cpu
pod_num = 需要计算的数量
 # 计算 min_pod_num，系数 * 1.2 或 1.5
pod_num = max(week_max_use_server_cpu * 1.2 / 5, week_max_use_istio_cpu * 1.2 / 5)
```

#### 内存Request推荐值

取一周最高的内存使用作为 request，limit = request * 1.2 或 1.5
